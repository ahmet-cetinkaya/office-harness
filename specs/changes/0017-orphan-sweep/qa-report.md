### Scope of the automated evidence

- `H/tests/server_sweep.rs` and `H/tests/server_crash.rs` run the real server binary, kill it with SIGKILL, and start it again. They use stand-in CLIs (shell scripts) and real stand-in processes. They read process start times from `/proc`, so they run on Linux only. Nothing in them runs on macOS or Windows.
- `H/tests/session_processes.rs` runs an in-process server and real stand-in processes on Linux and macOS (`cfg(unix)`). It checks what the recorder stores while a session runs.
- The T1 process inspection tests (`T/tests/process_inspection.rs` and the unit tests under `T/src/services/process_inspection`) run on Linux, macOS, and Windows in CI. Locally they ran on Linux only. They check the identity read, the match, and the end through a handle, on real child processes of the test.
- The sweep unit tests (`H/src/sweep/*.tests.rs`) use a fake inspector. They cover the OS refusals, the boot time rules, and the re-check before each end on every OS, but they do not touch a real process.
- A real "could not end" needs a process of another user, so it is covered by the fake inspector only.
- The server tests run with the default grace period of 10 seconds only where a test names SC-001 or SC-003 (the 30-agent test). The other sweep tests set a grace period of 1 or 3 seconds.
- The Playwright tests run against a mock core, so they prove the panel and the dialog, not the real server.
- The Rust gates exclude the `office-harness-desktop` crate. CI builds it on all three OSes. This change does not touch that crate.

## Known gaps

- The real-process sweep tests (`server_sweep.rs`, `server_crash.rs`) run on Linux only. macOS and Windows have the T1 handle tests and the fake inspector unit tests, not a sweep after a server kill.
- A real "could not end" (another user's process, or a refused kill) was never run. It is covered by fake inspector unit tests only.
- On macOS and on a Linux kernel before 5.3 there is no process handle. A process that exits and whose id is reused between the check and the end request can be ended by mistake (spec A10). The README documents it. The T1 tests run the no-handle path on Linux (`SystemProcessInspector::without_pidfd`), but no test can make the id reuse happen.
- The stored-command race (T3 note): a helper that execs between the store of its command line and the kill shows as "left: other command line", not "ended". The store replaces the line within 10 s (FR-011), so the window is short.
- PB-2 (no CLI file is touched) has no test.
- Several rows use database edits in place of real events: the other start time and the other command hash (SC-002), the helper limit flag (SC-008), the not readable process (SC-005), and the deleted identities of a session from before the change (SC-005).
- Plan and code differ in these places (PLAN.md, Execution notes):
  - A client reads the sweep state with the `sweep.state` request and follows the `office.sweep` event. The plan said a field in the hello answer.
  - `resume.plan` keeps its `agents` key: `{sweeping: true, agents: []}` while the sweep runs.
  - The server writes one `leftover_kept` row per agent, because a notification row names one agent. The desktop holds back the OS notification and sends one for all agents when `office.sweep` says `done`, or 1.5 s after the first row for a client that joined during the sweep.
  - The audit entry and the `ended` mark share one transaction, so the idempotency key route of D6 was not needed.
